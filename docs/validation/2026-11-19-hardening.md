# 2026-11-19 工作流加固验收（脱敏候选）

## 当前结论

源码独立复审、68 项自动化检查、隔离 CLI 闭环以及 Desktop 普通需求入口/实施/审计/修复复验均通过。已备份并应用到全局 MyCodexConfig；GitHub 发布结果以仓库提交为准。Desktop 与 CLI 证据分别核对，未用 subprocess 就绪检查冒充会话内 MCP 调用。

## 变更与已关闭问题

- 验收脚本共用隔离 home、真实会话回执、末行精确 verdict、审计源码身份和执行者独立性检查。禁止通过文本出现 PASS、预设 session ID 或模型自述伪造结果。
- 失效登记按条目隔离，保留原 registry；无关工程仍可用。失效原工程、祖先策略和同源 worktree 禁止降级自动发现。目的 worktree 缺规程时在写入/备份前拒绝；已删除子目录通过最近存在的 Git 祖先识别其原约束。
- 审计职责标签不绑定 provider/model，保留旧职责标签的报告兼容，不减弱独立会话门禁。
- BMAD 固定资源适配为只读上下文/结果；直接检查授权 worktree 和基线，无需生成临时 diff/报告。保留上游来源，重算适配后输出哈希。
- 七项技能补齐隐式调用 UI 元数据；入口在首次澄清前读取技能并检查真实工具。缺少 MCP 明确降级，原生读取资源不算 MCP 成功。
- 独立计划复核失败后，合成测试把问题交回原规划会话，修订后由原评审会话复核。不同于产品用户批准，测试操作者的批准仅适用于一次性 fixture。

独立代码复审发现的 H2-LINKED-DEST、H2-MISSING-SOURCE、H4-DIFF-PREREQUISITE、H5-READ-CONTENT、H1-PLAN-VERDICT 和 H6-PLAN-CONTRACT 均修复并复审关闭；独立评审不代替执行者运行测试。

## 使用与边界

全局已应用 release `90e6c84b9d4f318a6f0a`，与 Desktop 工程级验收所用候选一致。应用后的 stdio initialize、quality_info 与固定 BMAD 资源读取通过，证明安装就绪；当前旧会话没有新注入 quality 工具，因此不把该检查称为新全局会话原生调用。新任务读取最新配置，旧任务无需为此重启。

本次只证明一个小型 Python 工程的普通需求触发及完整修复闭环，不保证每个模型/每次任务自动选择全部技能。BMAD 只核实实际读取的资源，不宣称完整多视角 BMAD 审计认证。Desktop 最初拒绝跨对话代替用户确认，使用者在目标对话直接确认后才继续；未绕过该边界。

后续在新机器或新版本中，可按 [Desktop 验收](desktop-acceptance.md) 重做同类验证。保留真实模型档位、身份、命令原始输出及源码摘要；机器路径、原始日志和会话标识不进入公开仓库。
