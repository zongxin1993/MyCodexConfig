# Rust 适配验收（2026-11-19）

## 范围与隔离

新增 `codex-rust-workflow`，由实施/审计入口按 Rust 任务调用；保留具体诊断使用的 `codex-rust-diagnostics`。包含工具链/edition/MSRV、Cargo 包与 features/targets、编译/Clippy/行为测试、错误与并发/unsafe 审查的分层参考。仓库自身规程优先，不自动改变依赖、工具链或全局模型档位。

配置修改位于独立 Git worktree；真实小工程使用另一个一次性 Git 主仓库和 linked worktree。Rust 工具链安装于测试专用目录，没有写入用户默认 Cargo/Rustup 环境。原始日志、凭据、会话标识和机器目录不上传。

## 验证环境

- 宿主：macOS，`aarch64-apple-darwin`。
- Rust/Cargo：1.100.0；测试专用 Clippy、rustfmt。
- Codex：真实 CLI 会话，每次显式传入 `model_reasoning_effort="low"`。
- 认证：独立 staging home，文件凭据；拒绝活动 home、认证符号链接/共享 inode；Rust 测试剥离标准 API 密钥变量并强制文件存储。自定义 provider 的其他认证代理/变量不在通用隔离保证内。
- 无外部 Rust 依赖；Cargo 使用 lockfile/offline。该结果不是 MSRV 1.74 或其他平台的执行证明。

## 自动与原生检查

Python 53 项测试通过，覆盖原有安装/门禁兼容以及新增的失败退出码与原始日志、源码改变拒绝、证据目录隔离、发行包排除构建产物、Rust 技能参考安装、会话事件缺失/错误、伪 PASS、活动 home 与认证隔离。

`check_rust_fixture.py` 在独立证据目录保存完整原始日志、命令/cwd、工具链版本、前后源码 SHA-256 和退出码；源码改变或任一必要检查失败即 BLOCKED。它不会把 Cargo 输出写入被检查的源码树。

## 真实模型闭环

最终结果：PASS。最终验收轮的澄清、计划、实施、独立审计、原执行者修复及独立复审均完成，推理档位为 low。编译和 Clippy 负向控制均实际退出 101；实施、种子缺陷及修复后的六项检查均退出 0。独立审计明确定位 65,536 边界并返回 BLOCKED；修复后回归测试 `permits_exact_depletion_at_65536` 拦截同一缺陷，独立复审返回 PASS。实际会话事件确认实施/修复为同一会话、审计为另一会话，fixture 主检出内容与 HEAD 均保持不变。

测试需求为容量预留：正数请求在容量内返回剩余容量；零请求优先返回 ZeroRequest；超额返回 Insufficient；包括恰好耗尽及完整 u32 范围，不改变调用者状态。

- 编译负向控制：故意返回错误类型，须实际失败并包含 E0308。
- Clippy 负向控制：故意引入 let-and-return，须在 `-D warnings` 下失败并包含 clippy::let_and_return。
- 同一实施会话完成澄清、计划及批准后的实施；实际读取 Rust 技能，运行原生检查。
- 操作者在一次性工作树注入只拒绝容量 65,536 恰好耗尽的语义缺陷。既有六条 Cargo 门禁仍通过；独立审计仅获得需求与源码，未获得种子位置/触发提示。
- 独立审计必须 BLOCKED 并给出位置、严重性、影响范围与修复价值；原实施会话接回问题修复并加回归。
- 修复后重新注入同一缺陷，新增测试必须实际 FAILED；恢复修复字节后，由独立评审核对绑定当前源码的完整原生日志并复审。
- 每轮须有唯一真实 thread.started；恢复会话必须匹配实际标识，评审者必须不同于实施者。不能从请求参数回填标识来认证闭环。

复审保持源码只读。Cargo 构建需要可写 target，由隔离验证进程运行；评审者核对 checks.json、原始日志和实际源码摘要。早期探索轮因试图在只读沙箱重跑 Cargo 而诚实 BLOCKED，记录保留，不计作最终通过。

## 独立适配审计与限界

独立审计发现并修复了：变异/回归证据不够严格、会话身份可能回填、target 被递归发行、负向控制误判任意失败、staging 认证共享风险。修复加入对应保护和回归测试。独立复审核对最终源码与原始执行证据，重新计算的源码摘要与修复检查收据一致；五项审计问题全部关闭，无新的发布阻断。

未验证真实 Desktop 逐屏交互、MSRV、交叉编译、全部 features、unsafe/Miri、并发持久化恢复或大型业务工程。本次小工程通过不能扩展为这些场景的质量认证。
