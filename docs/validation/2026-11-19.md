## 两轮真实模型工作流

每轮均新建一次性 Git fixture，primary 保留基线，仅 linked worktree 实施。需求和计划批准由测试操作者脚本模拟，**只适用于 fixture**。

| 阶段 | 实际动作与结果 |
| --- | --- |
| 需求澄清 | 真实会话按 grilling 思路提出关键问题；源码未变化 |
| 计划 | 同一会话接收明确输入/异常/顺序/无副作用要求，给出需求与验收案例；源码未变化 |
| 实施 | 同一会话在现有 linked worktree 实现 `normalize_ids`，运行标准库单元测试，通过 |
| 缺陷注入 | 验证脚本显式将实现替换为缺少校验的去重逻辑，以验证审计拦截能力；不是业务代码事故 |
| 独立审计 | 新会话读取当前源码/测试/BMAD 资源；报告 BLOCKED，识别容器及元素校验缺失 |
| 修复复验 | 将实际问题回报交给原实施 session；修复并再次运行测试，外部操作者也独立运行原生测试通过 |
| 独立复审 | 原独立审计 session 重新读取修复后的当前源码，关闭原问题并给出 PASS |
| 主树检查 | primary 的 HEAD 和 Git 状态保持原样；实际 worker/reviewer 标识不同、修复 worker 与原 worker 相同 |

原始模型事件、会话 ID、机器目录和测试日志仅留在本机私有证据目录，未提交到仓库。公开报告不把脚本批准解释为产品用户批准，也不把两次小任务结果推广为所有工程质量保证。
