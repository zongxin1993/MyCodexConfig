# Codex 工作流加固计划

用户已批准按只读评估发现的顺序修复；先备份，不打扰已有任务，云端验收用 low。全局应用、发布以实际验收为条件。

| 需求 | 修改边界 | 验收 |
|---|---|---|
| H-1 验收不可误报 | Python/Rust 共用会话、隔离鉴权、终态结论和只读源码校验 | 缺失/重复/错会话回执、正文提及 PASS、审计修改源码、不同修复执行者必须失败 |
| H-2 登记失效不影响无关项目 | Runtime 逐项隔离缺失根目录/规程，登记器保留原配置 | 无关正常项目可登记；目标、祖先和同源关联 worktree 失效时阻塞，不能降级自动发现 |
| H-3 角色不绑定模型 | 中性审计职责标签；旧标签仅兼容已有报告 | 原有门禁仍验证职责和独立会话，新标签可通过，实施职责冒充审计被拒绝 |
| H-4 审计始终只读 | 适配后的 BMAD 步骤、来源说明、输出哈希 | 不再要求评审者写计划/报告/临时文件；资源完整性验证仍生效 |
| H-5 隐式技能与工具发现 | 七项 UI 元数据；入口能力检查、缺少 MCP 的明确降级 | 普通需求自行读取技能并调用实际 quality_info；简单翻译不启动工程流程；以原始调用记录核实 |
| H-6 完整流程与 Desktop | 独立计划复核、实施、独立代码审计、同执行者修复及复审 | CLI 与 Desktop 分开验收；不得用显式技能提示或 CLI 结果冒充 Desktop 结果 |

非目标：修改模型/provider/凭据/hook，修改 OpenCode、NAS 服务或原工程，重启现有任务，批量迁移用户 registry。

独立计划复核指出：关联 worktree 不可清除原登记的隔离状态；隐式触发要有实际读取/调用证据。计划已纳入这两个要求并复审通过。

宿主电脑控制禁止操作 Codex 应用，Desktop UI 自动化目前无法运行，不可绕过。先完成隔离候选验证，保留 Desktop 人工验收门槛；尚未满足时不应用全局、不发布。
