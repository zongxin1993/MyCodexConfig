## 独立审计及修复

GCR-01..06：修复否定/引用批准误识别、旧 PASS 遮盖新阻塞、派发身份关联、检查清单竞态和失败残留、MCP 成功判定过宽及暂停被普通提示解除。GCR-R7：修复 Git --output、ext-diff、textconv 的只读误分类。上述问题经独立复审关闭。

安装前另发现 Desktop 将原生 TUI 设置插入管理标记内部。安装器现在保留这些原生表及外部技能配置，支持含行首方括号的多行 TOML 值；对不明确归属的 MCP 扩展在写入前拒绝，避免静默丢失。CFG-01..03 复审驱动增加配置并发写保护与异常回滚保护：检测到外部更新时保留新内容并明确报告，拒绝盲目覆盖。

## 宿主要求与局限

原生 hooks 必须经宿主信任；安装成功不等于 hooks 已运行。新命令路径需要重新审阅信任。只有获得新 startup 回执的会话启用守卫，既有运行任务不会凭空获得新的验收状态。

创建对话或 send_message_to_thread 的委派消息在实际宿主记录为 codex_delegation，不触发直接 UserPromptSubmit 批准。测试中由用户在专用对话直接发送需求和准确计划批准后推进。

工程守卫不替代宿主沙箱；任意 shell、未覆盖专用工具及宿主 fail-open 仍有边界。原始日志、凭据、用户配置、会话标识和私有状态不上传。原工程读取权限仍由宿主管理，注册不授予访问权限。
